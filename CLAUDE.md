# CLAUDE.md — 75 Hard app (project memory)

Hebrew RTL, phone-first PWA for the user's personal 75 Hard rule set. Vanilla HTML/CSS/JS, **no build step, no backend, no dependencies**. Data lives only on the device (localStorage state + IndexedDB photos). See [README.md](README.md) for features, deploy and layout.

## Decisions (user-confirmed)
- Hosting: **GitHub Pages, public repo** (free account). User chose this over Netlify so pushes auto-deploy.
- **Privacy:** the repo is public, so the wording of the two personal rules (daily rule #2, weekly-limited rule #3) must NEVER appear in code, data or docs. Only the neutral labels live in `Day.newState().settings.ruleNames`; the user renames them on-device in Settings. Verify with a grep before any publish.
- Start date is chosen by the user (never "first open"). Day ends via the **"סיים את היום"** button; fallback auto-close at `settings.cutoffHour` (default 05:00).
- A missed item → **warn, allow fixing a mis-tap, user confirms** the restart. Never reset silently. Best streak + failed attempts kept (`state.best`, `state.history`).
- **Round 2 (after first real use):** negative rules are NOT checkmarks and NOT tracked (honor system) — they live as reminders (Today's collapsible "כללים לזכור" card + Rules tab). The weekly-limited rule was removed entirely (no counter). Reading is a single checkmark (no pages/book). A manual "restart from Day 1" (`Day.manualRestart`, Settings→backup tab) replaces rule-slip tracking; new Day 1 = tomorrow.
- **Weekly training quota (round 5):** 14 sessions per calendar week (Sun–Sat): `str_up` 2, `str_low` 2, `sport` 2, `run` 1, `walk` 5, `mob` 2 (`data/training.he.js`). Each workout record has `cat` (+ `plan` text); pure logic in `js/training.js` (`weekProgress`, `suggest`, `effective`, `hints`) with tests. It is a GOAL only — `evaluateDay` never looks at it; only the 75 Hard rules reset the run. First/last weeks of the 75 days are "partial" (counts, no target). With exactly 14 slots for 14 sessions, "need == slots left" is simply ON TRACK (status `ontrack`), `behind` = can't finish this week; don't add a "no room to skip" warning (it would nag on every perfect day). The per-weekday template (`settings.weekPlan`) was removed; `Store.normalize` pins the old effective plan onto already-DONE workouts (`materializeLegacyWorkouts`) so history keeps counting. Slot choice: explicit `day.wN.cat/plan`, else the top suggestion (`Training.effective`); Start/manual pin it onto the record.
- **Sticky note (round 3, show added round 6):** finishing a day earns a note counting DOWN — day 1 → 75 … day 75 → 1 (`Day.noteNumber`). Shown full-screen once (`App.render` → `Day.pendingNote` → `Views.note.openToday`), before the milestone dialog; days auto-closed at 05:00 show on next open; a catch-up shows only the newest note and marks the older ones shown (no pop-up flood). `state.notesShown` ('attempt:dayNumber'); old saves without it get every already-finished day marked shown in `Store.normalize`. Drawn as inline SVG in `js/note.js`. **The show:** random pastel colour per day (`Note.PALETTE`, 7 colours; `Note.colorIndex(attempt, day)` is a stable hash, never the same colour two days running, so the wall's minis match), fireworks on a canvas (`js/fireworks.js`: pure `createParticles`/`step` + loop; a pop at the peel, rockets + burst at the fall), and the note swings wider like a pendulum (`noteWobble`) then falls off-screen (`noteFall`). Timeline constants live in `Note.TIMING` and are passed to CSS as `--wob-at` / `--fall-at`, so the CSS and the fireworks timers can't drift. Tapping a wall note uses the calm mode (`note-calm`: gentle sway, no fall, no fireworks). `prefers-reduced-motion`: still note, no fireworks. In-app only (user declined save/share).
- **Plate builder (round 4):** Meals tab = build-a-plate from `data/ingredients.he.js` (~90 items: id, part, grp family, slots b/m/bm); pure logic in `js/plate.js` (`swaps`, `compose`, `completeness`, pantry toggles) with tests. `state.pantryMissing` = ids NOT at home (default everything is). Swaps = same part + same meal + still available, same `grp` first; a test guarantees every item always has substitutes (adding items: keep ≥5 per part per meal and a non-empty swap set). Not built (user declined): effort filter, favorites, label flags, custom ingredients. Original dishes = "הצעות מוכנות"; eating-out guide in `Meals.EATING_OUT`.
- **Statistics (round 7):** a "סטטיסטיקות" section in the Progress tab (pills: אימונים / ארוחות) for the CURRENT attempt only (`js/stats.js` pure + `js/views/stats.js`, tested). Workouts: totals, minutes, average, outdoor %, per category, per weekday, and a newest-first week list (stacked colour bar, `n/14`, partial weeks flagged). Meals: counted over FINISHED days only (an open day can't be judged), adherence = logged / (3 × days), plate-formula rate, protein sources and top ingredients. Meal detail comes from `day.mealInfo[task]` = `{src:'plate', items:[ids]}` or `{src:'quick', cat}`, written by `Day.setMeal(..., info)`; meals logged before this existed count as "logged" only (text-only = untracked) except ready-made dish text, which is recognised by matching `Meals.CATEGORIES`. Un-ticking a meal deletes its text AND info. Protein sources cover plate-builder meals only. `stats.js` must not capture `Meals` at load time (meals.he.js loads after it) — it looks it up when called.
- Water: bottle/glass buttons + a free whole-ml input (1–5000, button-only add; "−" bottle remains the correction path).
- Workout gap default 3 h (source doc says 3–4 h); setting offers 3 / 3.5 / 4.
- iOS web apps can't push-notify while closed → in-app banners + a generated list for iOS Reminders (`js/reminders.js`).

## Architecture notes
- `js/day.js` is pure logic with the clock passed in (`now` ms) — all lifecycle rules live there and are covered by `tests/tests.html` (run it after ANY change to day.js/store.js/reminders.js; must show `0 failed`).
- Logical day = cutoffHour→cutoffHour; computed from LOCAL hour (not ms math) so DST can't shift it.
- Views render HTML strings; interactions use `data-act` / `data-change` delegation registered with `App.act(name, fn)`. Escape every user-provided string with `App.esc`.
- `App.state` is replaced wholesale on backup restore/reset — views must read `app.state` live, never cache it.
- Photos: downscaled to ≤1600 px JPEG, keyed by day key; backup embeds them as data URLs.
- `sw.js`: same-origin network-first (fresh when online, cached offline); the precache `SHELL` must list every file the app loads (one 404 breaks offline install) — update it and bump `CACHE` when adding files.

## Gotchas learned the hard way
- **Saves outlive releases.** Real users hold data from older versions. `Store.normalize` must merge defaults into a *fresh copy of the defaults* (not into the saved object) so settings added later exist on old saves, and any removed/renamed field needs a migration there. Add a test with a save shaped like the *previous release*, not just an empty one.
- **`tests/tests.html` is deployed and shares an origin with the app.** Tests must never touch the real `localStorage`: storage tests use `Store.useBackend(fakeStorage)`; a test asserts the real `75hard:*` keys are unchanged. Never add a test that writes/removes real keys.
- The browser pane is Chromium: it cannot reproduce iOS-Safari-only layout bugs (e.g. date inputs ignoring `width`). Apply the known CSS fix, check no overflow, and have the user confirm on the iPhone.

- **Deploy lag:** GitHub Pages serves `Cache-Control: max-age=600`, so a plain `fetch()` in the service worker can hand the phone files up to 10 min stale. The SW therefore fetches same-origin with `{cache:'no-cache'}` (ETag revalidation) and registers with `updateViaCache:'none'`. **Every release: bump `CACHE` in `sw.js` AND `App.version` in `js/app.js`** (shown in עוד, with a "בדיקת עדכון עכשיו" button that clears the app-file cache and reloads — never the user's data).

- **The browser pane can be hidden/minimized** (`tabs_context` says so): then no animation frames run and screenshots time out. Verify animations without frames: pause every `document.getAnimations()` entry and set `currentTime`, read computed transforms; for canvas loops, swap `requestAnimationFrame` for a manual pump. Don't claim you saw it.
